Architecture review — hn-enrich

src/hn_enrich/ · 2026-07-15 · plain-English edition · tracked in PRD issue #55

Five words this report uses, in plain English:

  • Module — any piece of code with an outside (what callers see) and an inside (how it works). A function, a class, a file.
  • Interface — everything you must learn to use a module correctly. Small interface = easy to use.
  • Deep module — you learn a little, you get a lot. Lots of work hidden behind a small interface. The opposite (shallow) means you learn almost as much as the module actually does for you.
  • Seam — the line where a module meets its callers. Tests and real callers should cross the same line.
  • Leverage / locality — the two prizes. Leverage: one implementation serves many callers. Locality: when something breaks, the fix lives in one place.

Six findings. Each one shows the real code today, a prototype of the change (nothing is implemented yet), and an ASCII picture. Each is filed as a GitHub issue. Decisions already documented in docs/concepts/trade-offs.md (Service-Locator deps, hand-written DAG, Postgres-as-queue, fake-by-default) are respected — none is reopened here.

1 · Six workers copy the same loop

issue #49 Strong — do this first

The problem, in plain words. Every worker file has two parts. The first part is the real work — for word_count it is literally one line: len(text.split()). The second part is the loop around it: figure out which items still need work, catch errors, count retry attempts, write the result to the ledger, commit. That loop is copied, by hand, into all six worker files.

And the tests point the wrong way: the one-line functions have many unit tests, while the loop — where real bugs hide — is only tested when Docker is available. Two invisible rules make it worse: every worker must remember to call the staleness gate first, and must remember session.commit() at the end. Forget either, and things break silently.

The code today — the loop in word_count.py:86, and again (with try/except) in ai_class.py:102

Prototype — worker_run.py (new module) and word_count after the change

# worker_run.py (PROTOTYPE — the Template Method pattern: shared skeleton, one step per worker)
def run_worker(ids, *, worker, version, retry_budget, process):
    settings = deps.settings()
    with deps.enrich_session_factory()() as session:
        repo = EnrichRepo(session)
        todo = repo.runs_to_do(ids, worker, version, settings.pipeline_generation)
        for item_id in todo:
            error, attempts = None, 1
            try:
                outcome = process(session, item_id)      # the worker's ONE step
            except Exception as exc:
                attempts = repo.attempts_for(item_id, worker) + 1
                outcome = failure_outcome(attempts, retry_budget)
                error = str(exc)
            repo.record_run(item_id, worker, outcome=outcome,
                            attempts=attempts, version=version, last_error=error)
        session.commit()          # written once; no worker can forget it


# word_count.py after — keeps its model, upsert, and pure logic; only the loop leaves
@task(name="word_count")
def word_count(ids: list[int]) -> None:
    def process(session, item_id):
        text = _stored_text(session, item_id)
        if text is None:
            return SKIPPED        # the worker still owns the na/skipped decision
        _upsert_count(session, item_id, count_words(text))
        return OK
    run_worker(ids, worker=WORKER, version=VERSION, retry_budget=1, process=process)
  • Locality: the retry/ledger/commit protocol is fixed once, fixed everywhere.
  • Leverage: one implementation, six callers.
  • The tests finally land on the risky code — and run fast, without Docker.
  • "One file per worker" survives: each file keeps its name, version, table, upsert, pure logic.

2 · tasks/post_metadata.py does almost nothing

issue #50 Strong — small & safe

The problem, in plain words. This 50-line file has exactly one line of real work: has_url = item.url is not None. The rest packs five values into a box (CoreProvenance) — and the only caller immediately unpacks the box again, field by field. Learning this module costs as much as it does for you. 3 · The status words have no single owner

issue #51 Worth exploring

The problem, in plain words. The status column can hold six words, defined in two files: workqueue.py owns "not finished" (pending, running), finalize.py owns "finished" (success, partial, degraded, failed). The system is only safe if the two sets never overlap — the claim query picks by one set, the nightly heal by the other. But no production code checks this. Only a unit test does, and the test has to rebuild the finished set by hand, because finalize never exports it. Add a new finished status tomorrow and forget the test — the safety check quietly stops covering it.

BEFORE: one column, two owners, and the rule floats in a test

  │ running       │           │ degraded  failed       │
  │ UNSETTLED=(..)│           │ (no SETTLED tuple!)    │

          └───────── who checks ──────────┘
                 they never overlap?
          ┌──────────────────────────────┐
          │ one unit test, rebuilding    │  ← easy to forget to update
          │ the settled set by hand      │

AFTER: the rule owns itself

                     │
                     ▼

Prototype — two tiny edits

    "status vocabulary overlap: " f"{set(UNSETTLED) & set(SETTLED)}"

  • The overlap rule gets an owner in production code, not just in a test.
  • A new settled status cannot dodge the check.
  • The heal query can use SETTLED instead of listing statuses inline (repo.py:384).
The docs deliberately give each half an owner (work-queue.md). That split stays — only the union gains a guard.

4 · The SSRF redirect rule is split across two files

issue #52 Worth exploring

The problem, in plain words. The pipeline fetches URLs from the public internet — attacker-influenced input. The guard refuses URLs pointing at private/internal addresses. The most important part of the rule: check every redirect hop, because a harmless-looking public URL can redirect to http://169.254.169.254/…. Today the guard function (one URL at a time) lives in politeness.py, but the loop that applies it to every hop lives inside the HTTP adapter in adapters.py. The two halves are held together by a docstring. The next fetching adapter (the future browser-based tracker scanner) must re-remember all of it from prose — and getting it wrong leaves no trace in any log.

The code today — the loop inside HttpxFetcher (adapters.py:95)

with httpx.Client(..., follow_redirects=False, ...) as client:   # part 1 of the rule
    hop = url
    for _ in range(self._max_redirects + 1):                      # part 3: bounded
        assert_public_url(hop, resolve=self._resolve)             # part 2: EVERY hop
        response = client.get(hop)
        if response.next_request is None:
            return FetchResult(...)
        hop = str(response.next_request.url)
raise httpx.TooManyRedirects(...)

Prototype — politeness owns the walk; the adapter supplies one hop

# politeness.py (PROTOTYPE)
def walk_redirects(fetch_once, url, *, max_redirects, resolve=default_resolve):
    """The whole SSRF redirect rule in one place: never let the client follow
    redirects itself; judge each hop before touching it; give up loudly."""
    hop = url
    for _ in range(max_redirects + 1):
        assert_public_url(hop, resolve=resolve)
        result = fetch_once(hop)             # transport-specific, injected
        if result.next_url is None:
            return result.response
        hop = result.next_url
    raise TooManyRedirects(f"gave up after {max_redirects} redirect(s) at {hop!r}")
  • Locality: a security rule gets one home and one test surface.
  • The next fetching adapter cannot forget the rule — it never sees it.
Honest caveat: only one adapter fetches today, and normally one user does not justify a seam. The argument for doing it early: this failure mode is silent — no log, no failing test, just an open hole. Safety rules earn a home before the second user arrives.
